# CJK TB Coverage Recall Design

## Goal

Fix the root cause of CJK terminology candidate recall misses in long source segments, without regressing English profile matching behavior.

The motivating failure is project `花园`, where the mounted TB contains:

- Source term: `喵居商店`
- Target term: `Boutique Miaou Maison`

The source segment contains `喵居商店`, but the TB flow trace shows:

- the term exists in the mounted TB,
- repo candidate recall does not include it,
- fallback full mounted scan is skipped because other FTS candidates were found,
- final matches do not include it.

The fix must make CJK terminology recall coverage stronger while keeping final matching strict.

## Non-Goals

- Do not change AI request retry behavior.
- Do not make full mounted TB scans part of the normal path.
- Do not change English profile alias, plural, singular, acronym, or final-position matching logic.
- Do not add user-visible errors or settings for this behavior.
- Do not optimize unrelated TM/TB behavior.

## Root Cause

TB matching is a two-stage flow:

1. Build a search plan from source text.
2. Use that plan to recall TB entry candidates.
3. Run final term-position matching against only those candidates.

The failure happens before final matching.

Two recall weaknesses combine in the failing case:

1. `serializeTokensToSearchText` drops non-text tokens and joins text tokens directly. This removes tag boundaries, so source text like `...喵居商店购买获得{1}{1}5.当...` becomes `...喵居商店购买获得5.当...`.
2. CJK FTS fragments are bounded and sampled from the whole source. In long source text, the fragment budget may not cover a term in the middle or back half of the source.

Because repo candidate recall still finds other entries, `TBService.findMatches` does not fall back to a full mounted TB scan. The missing term never reaches final matching.

## Design

### 1. Preserve Token Boundaries in Search Text

`serializeTokensToSearchText` must keep only text content, but every non-text token must contribute a space boundary.

Example:

```ts
serializeTokensToSearchText([
  { type: 'text', content: '喵居商店购买获得' },
  { type: 'tag', content: '{1}' },
  { type: 'tag', content: '{1}' },
  { type: 'text', content: '5.当任意单个小鱼干' },
]);
```

Expected search text:

```text
喵居商店购买获得 5.当任意单个小鱼干
```

This prevents artificial CJK/digit or CJK/CJK concatenation across tag boundaries. It also keeps terminology QA behavior more honest: tags do not become searchable content, but they do remain boundaries.

### 2. Strengthen CJK Exact Candidate Recall

For CJK-like source runs, exact lookup terms must cover CJK n-grams from length 2 through length 8.

This deliberately excludes one-character CJK coverage from the strengthened exact recall path. Single-character terms are too noisy for this fix and must not be generated by the CJK exact n-gram coverage.

Examples that must be covered:

- `小鱼干`
- `交换喵`
- `偷吃喵`
- `喵居商店`
- longer CJK UI/entity terms up to 8 characters

Exact candidates must continue to be merged before FTS candidates, so high-confidence source-normalized terms cannot be displaced by noisy FTS rows.

### 3. Use Coverage-Oriented CJK FTS Fragments

CJK FTS fragment generation must distribute bounded fragments across the full CJK source instead of over-focusing on the earliest available fragments.

The implementation must keep a maximum fragment budget, but choose fragments by source-position coverage. A bucketed or round-robin-by-position strategy is acceptable if it guarantees that long CJK runs contribute fragments from the start, middle, and end of the source.

This keeps FTS useful for terms that are not captured by exact lookup, while avoiding unbounded SQL query growth.

### 4. Keep English Profile Isolated

The English profile in `termMatchingProfiles.ts` remains responsible for:

- `account` matching `Accounts`,
- `real time` matching `real-time`,
- `US` matching `U.S.`,
- multi-word final-word plural handling,
- acronym safeguards.

The CJK coverage changes belong to strict search-plan generation and must only affect CJK-like tokens/runs. English alias generation and English final-position fallback must not be changed.

Boundary-preserving search text is allowed to affect English text only in the sense that tag boundaries become spaces. That is the correct search-text meaning for text split by inline tags.

## Data Flow

After the fix:

1. Segment source tokens are serialized with tag boundaries preserved as spaces.
2. `buildTermSearchPlanForLocale` delegates to the strict plan for zh-CN.
3. The strict plan generates CJK exact lookup terms covering 2-8 character CJK terms.
4. The strict plan also generates bounded FTS fragments with full-source positional coverage.
5. `TBRepo.searchProjectTermEntries` searches exact candidates first, then FTS candidates, then merges under the existing candidate limit.
6. `TBService.findMatches` final-filters candidates with `findTermPositionsInTextForLocale`.
7. Only candidates with real source positions become TB matches and enter the AI prompt.

For the `花园` segment, `喵居商店` must be recalled through exact source norm and then accepted by final matching.

## Performance Boundaries

- No normal-path full mounted TB scan.
- CJK exact coverage is limited to 2-8 character n-grams.
- CJK FTS fragments remain bounded by a fragment budget.
- Existing candidate limits remain in force.
- Exact candidates continue to sort/merge ahead of FTS candidates.
- English profile alias budget and behavior remain unchanged.

The expected cost increase is limited to CJK source search-plan generation and bounded SQL `IN` batches for exact lookup. The design favors recall correctness for CJK terminology while avoiding unbounded database scans.

## Error Handling

No new user-visible errors are introduced.

Existing behavior remains:

- empty source text returns no matches,
- missing project returns no matches,
- unmounted or disabled TBs do not contribute candidates,
- candidates without final source positions are discarded.

If the stronger search plan recalls extra noise, final matching filters it out before prompt construction.

## Acceptance Criteria

- `喵居商店` is recalled and final-matched in the garden TB flow.
- CJK long-text terminology recall no longer depends on early fragment-budget sampling.
- Tag boundaries no longer create artificial adjacent search text.
- English profile behavior remains unchanged under existing tests.
- No normal-path full mounted TB scan is introduced.
