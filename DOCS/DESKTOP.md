## Workspace navigation

Project sections share the header's left gutter. Tasks, resource panes, and Settings retain their own maximum widths without centering. Task titles and rename fields share one icon column; confirmation and background-job progress align beneath the title with a small optical inset.

The renderer uses a fixed, expanded project sidebar and one content area. Project folder icons contain T, R, or C for translation, review, or custom projects; projects without an explicit type use T. CAT hides the sidebar to use the full workspace width; returning to the project restores direct project navigation. Project action menus float outside the scrolling sidebar, support keyboard navigation and dismissal, offer persistent pin/unpin actions, and retain the typed-name confirmation before deletion. Pinned and regular project sections collapse independently, with those local sidebar preferences restored across launches.

Project names open the project page with Tasks, resource tabs, and project Settings (each task is an existing imported file); global translation memory, term bases, and Settings open in the same area. Clicking a task title or its row's non-control space opens the file. Rename fields and action buttons handle their own clicks. Task actions remain visible in each row and wrap on narrow windows. Rows use quiet secondary actions, a confirmation progress bar/count, and a separate QA issue count; project-type labels are neutral. The sidebar's New project icon remains keyboard accessible beside the wordmark. Global TM/TB catalogs use two-column cards, falling back to one column when the content area is narrower than 720px. Project resource tabs still manage project mounting. Settings and TM/TB entry previews are page components; previews retain the existing ten-row limit.

Project Settings uses one [`ProjectSettingsPane`](../apps/desktop/src/renderer/src/components/project-detail/ProjectSettingsPane.tsx) with AI and QA sections and a shared Save/Discard footer. AI selects a globally configured provider and edits the project prompt; runtime prompt preview and testing are collapsed initially. QA lists the existing rules and instant-on-confirm option, and appears only for translation projects. Tasks retains Translate and QA execution actions; an unavailable provider links to AI settings. The former Tasks AI disclosure and QA modal are removed. The project content area reserves scrollbar space so expanding settings or changing tabs does not shift the form horizontally. AI and QA drafts live at project level, survive section and Tasks/TM/TB switches, and save or discard independently. Saving disables that section's form; failures retain drafts, and a delayed save cannot update a different project. [`useProjectQASettings`](../apps/desktop/src/renderer/src/hooks/projectDetail/useProjectQASettings.ts) owns QA draft/save state beside the existing AI controller. [Settings behavior tests](../apps/desktop/src/renderer/src/components/project-detail/ProjectSettingsPane.test.tsx) cover draft retention, discard, failed and delayed saves; the [settings smoke suite](../apps/desktop/e2e/project-settings.smoke.spec.ts) verifies navigation and persisted values in Electron.

Version, manual update checks, and update status live in [SettingsPage](../apps/desktop/src/renderer/src/components/SettingsPage.tsx) > Updates. [useAppUpdates](../apps/desktop/src/renderer/src/hooks/useAppUpdates.ts) owns the app-wide subscription and notification lifecycle; the settings tab renders its controller and reads the application package version.

`App` composes the workspace; [useWorkspaceNavigation.ts](../apps/desktop/src/renderer/src/hooks/useWorkspaceNavigation.ts) owns guarded transitions. The CAT editor registers an awaited save guard before leaving a file. Its Back action saves first, then restores the project workspace and navigation. The content area is inert during a transition so new input cannot race pending writes. Failed saves restore interaction in the current editor and retain the draft. Overlapping transitions are blocked. Returning to a file restores its last active segment for the current app session when it remains in the filtered list; existing per-file filter persistence remains authoritative.

[Navigation tests](../apps/desktop/src/renderer/src/hooks/useWorkspaceNavigation.test.ts) cover delayed saves, failure, cancellation, and guard cleanup. [Sidebar tests](../apps/desktop/src/renderer/src/components/WorkspaceSidebar.test.tsx) cover project menus and direct navigation. The [editor smoke suite](../apps/desktop/e2e/editor-engine.smoke.spec.ts) exercises CAT return, saved drafts, sidebar restoration, and visible task actions in an isolated Electron user-data directory.

## UI foundation

[`components/ui`](../apps/desktop/src/renderer/src/components/ui/index.ts) is the renderer's shared control boundary. Pages and domain components import controls here; Radix Dialog/Tabs, Floating UI, and Class Variance Authority are private implementation dependencies of this layer. Button variants follow the compact shadcn composition model while preserving the native React 18 control contracts; IconButton and ToggleButton delegate to Button, and all form fields share the same size variants. There is no separate workspace or CAT control implementation. The shared `Icon` component holds the adopted Lucide database, book, spreadsheet-file, settings-slider, and filter-funnel shapes; their license ships in `renderer/public/licenses/LUCIDE.txt`. [`components/ui/styles.css`](../apps/desktop/src/renderer/src/components/ui/styles.css) owns shared control styling, [`theme/metrics.css`](../apps/desktop/src/renderer/src/theme/metrics.css) owns control sizes and radii, and [`index.css`](../apps/desktop/src/renderer/src/index.css) owns application layout and editor rendering. Portals consume the same document-level tokens without local geometry overrides. Tailwind maps semantic utilities to these variables.

The CAT toolbar's **Editor appearance** button offers Sand, Classic, and Nord together with Chinese font, Western font, and text size in all project types. The workspace uses the approved Sand warm-gray surfaces and orange brand accent by default; existing saved choices remain authoritative. Settings > Appearance and the CAT popup render the same `AppearanceControls` composition. Classic retains the traditional warm surfaces with stronger semantic text contrast and is the initial editor preference; the choice is saved locally across files and launches. The shared [`AppearancePicker`](../apps/desktop/src/renderer/src/components/ui/AppearancePicker.tsx) renders theme color cards and segmented font/size choices using the shared `ChoiceGroup`; CAT only supplies its toolbar position and accessible label. [`ThemeProvider`](../apps/desktop/src/renderer/src/theme/ThemeProvider.tsx) applies the current surface's palette to the document root, so menus, dialogs, and feedback inherit it. The app shell composes the color and typography providers independently and selects the `editor` or `workspace` scope; [`themePreferences.ts`](../apps/desktop/src/renderer/src/theme/themePreferences.ts) keeps their saved choices independent. Leaving CAT restores the workspace preference, which defaults to Sand; the editor still defaults to Classic. Any workspace page can reuse the same picker and provider without introducing another theme implementation.

CAT groups AI Translate with QA, and hidden-character display with appearance. Sort, the paired source/target searches (including the target/context switch), Filter, and Clear remain on one filter row. Search fields share equal widths without coupling their divider to the segment columns. The header shows a compact confirmation progress line and count. CAT/Concordance use segmented tabs; reference metadata shows resource names with full provenance in the tooltip/accessibility label, retaining the Working TM distinction. The reference badge separates the two bodies without additional column borders. Segment number gutters retain their right border, and active targets retain the top/right/bottom outline and shadow.

Theme changes update CSS without remounting the editor. Storage failures fall back safely and do not block switching. Palette IDs, labels, and per-scope defaults live in [`colorThemes.ts`](../apps/desktop/src/renderer/src/theme/colorThemes.ts). [`palettes.css`](../apps/desktop/src/renderer/src/theme/palettes.css) owns every palette value; add or adjust colors there, not in individual components. Sand uses the official Radix Sand scale and momoCAT's existing orange logo accent. `brand-solid` owns the filled primary-action background (a deeper orange in Sand for warm-white labels), while `brand` is the contrasting small-text role; `brand-contrast` belongs on the solid fill. Both roles alias the existing accent in Classic and Nord. Logo and pinned-folder accents retain the original brand orange. Saved project settings use a neutral checkmark label; unsaved settings expose the primary Save action and neutral Discard action. Its source comments cite the official [Nord](https://www.nordtheme.com/docs/colors-and-palettes/) palette and distinguish its values from momoCAT's auxiliary tints and contrast adjustments. Retired Charcoal preferences migrate to Nord; Flexoki, Ivory, Light blue, and unknown values fall back to the active scope’s default. Search highlights, selection, caret, focus, workflow status markers, QA feedback, and TM/TB badges use semantic tokens as well. Status roles (`status-*`) and match roles (`match-*`) are independent of components; workflow and reference colors are separate from action and QA colors. [Preference tests](../apps/desktop/src/renderer/src/theme/ThemeProvider.test.tsx) cover restoration and storage failures; the [theme smoke suite](../apps/desktop/e2e/editor-themes.smoke.spec.ts) verifies palette colors, text contrast, portals, keyboard selection, editing continuity, and review projects in Electron.

Action colors follow intent: primary actions, selected choices, and running-operation progress use brand roles; auxiliary actions, persistent saved/in-use labels, and option-card backgrounds use neutral roles. Green is reserved for successful outcomes, confirmation progress, and added diff text, not an alternative action accent. Import column mapping uses brand for source/input, info for target/output, and neutral for context. Pages select existing semantic roles through the shared controls rather than introducing local color values.

Surface roles are shared across palettes: `navigation` holds the workspace sidebar; `surface` holds content and floating controls, `surface-chrome` holds toolbars, and `surface-panel` holds supporting panels. CAT's chrome and panel roles alias `editor-surface`. Segment rows alternate between `editor-surface` and the palette-owned `editor-surface-alternate`, with the number gutter, source and target sharing one row background. Alternation follows the current filtered/sorted display order in both virtualized and full lists. `border-subtle` separates regions and rows; `border` outlines controls. The active target retains its row background, clear focus outline, and the palette's `shadow-active` soft shadow shared with the selected TM result. Other reference results keep the base background without a shadow. All themes share the same filled reference badge palette: green for exact matches, blue for fuzzy matches, gold for TB, and neutral gray for concordance C. All reference badge lettering is white. Adjust these roles in the palette owner to tune the hierarchy without adding component-specific color values.

Workflow status uses a full-height 8px strip beside each target. Its separated hues are neutral gray for New, ochre for Draft, blue for AI Translated, and green for Confirmed. Review projects' AI Reviewed status shares the AI blue; it is not a separate human-review stage. QA never replaces that strip or tints the segment background. Error, warning, and info feedback use a colored icon and severity label with neutral message text; save failures use the same unfilled presentation. The status tooltip retains QA error/warning context, and confirmation checks keep their existing behavior.

The same appearance popup chooses Chinese and Western fonts and a source/target text size independently of colors. Color and typography preferences retain separate providers and storage keys. Chinese choices are Noto Sans SC and Noto Serif SC; Western choices are Source Serif 4 and Source Sans 3. The default pairs Noto Sans SC with Source Serif 4 at 16px; 14px is also available. Saved preferences without a size use 16px, and the retired Western Noto choice falls back to Source Serif 4 while preserving the Chinese choice. Source Sans 3 contains no Chinese glyphs. [`typography.ts`](../apps/desktop/src/renderer/src/theme/typography.ts) owns the catalog and scoped local preferences; [`TypographyProvider`](../apps/desktop/src/renderer/src/theme/TypographyProvider.tsx) applies them without remounting content. [`typography.css`](../apps/desktop/src/renderer/src/theme/typography.css) owns the interface and monospace font stacks, the named interface type scale, reference-body/metadata/badge sizes, and reading size/line height (14px or 16px, both with 1.7 line height). Tailwind text roles reference that scale; components do not contain arbitrary font-size utilities. Reference text keeps its own size role so changing interface labels does not change CAT reference-body text. Source/target and reference text share the `content-text` typography rule; CAT panel source, target, and lower source-comparison bodies use a compact 12px size, independent of the segment size preference; match badges remain 8px and reference metadata remains 9px. Workspace typography choices apply to TM/TB preview source, target, and note text through the shared `reading-text` rule. Controls retain a sans-serif interface stack. Pinned Fontsource packages bundle the fonts offline, with OFL notices in [`public/licenses`](../apps/desktop/src/renderer/public/licenses). [Typography tests](../apps/desktop/src/renderer/src/theme/TypographyProvider.test.tsx) cover scope isolation, restoration, older and invalid preferences, and storage failures. The [typography smoke suite](../apps/desktop/e2e/editor-typography.smoke.spec.ts) verifies local font rendering, both text sizes, persistence, and editing continuity. The theme suite uses an isolated [reading fixture](../apps/desktop/e2e/support/editorReadingScene.ts) for status, QA, reference, and highlight coverage.

- `Modal` owns dialog semantics, scrolling, backdrop, focus trapping, Escape and focus restoration. Every dialog has a title. Omit `onClose` for a blocking operation; `closeOnBackdrop={false}` only disables outside dismissal. Shared controls defer their `autoFocus` until the modal's focus boundary mounts. Dialogs portal in opening order; callers do not assign stacking overrides. `FeedbackHost` owns confirmation queues and typed-name validation, while job controllers retain cancellation and completion handling.
- `Menu` and `Popover` share positioning, viewport collision handling, portals and dismissal. A menu uses `MenuItem` for keyboard navigation and closes before its action runs. Anchors are elements or element refs. Dismiss callbacks explicitly close their popup and tolerate repeated calls; they do not toggle visibility. Popups opened inside a modal stay inside its accessibility/focus boundary; Escape dismisses the popup first. Editor selection remains in the editor controller, not in the popup.
- `Tabs`, `TabsList`, and `TabsPanel` own tab roles, panel associations, roving focus, arrow/Home/End navigation and automatic activation. The page still owns the selected value and data loading. Inactive page content remains unmounted as before. The `segmented` variant provides compact, softly selected reference tabs.
- `Button`, `IconButton`, `ToggleButton`, `Input`, `Select`, `Textarea`, `Checkbox`, and `Radio` preserve native events and refs. Buttons default to `type="button"`; form submission must opt into `type="submit"`. Button `variant` selects appearance, `tone` selects color (including `danger`), and `size` selects `xs` through `lg`. The `link` variant inherits surrounding typography and has no padding or size prop. Tone, variant, size, and field appearance belong to the control API; page `className` props express layout, visibility, and content typography only. Form appearance and sizing have one definition in `controlVariants`, shared with the button size scale. `SearchInput` owns its icon, inset spacing, and optional trailing action while forwarding the input ref and native events. `SearchInputGroup` owns the shared border, equal field widths, divider, and individual focus indication for paired searches. Native selects retain browser keyboard behavior.
- `ControlGroup` groups related icon buttons under one outline in horizontal or vertical layouts without changing their individual callbacks, disabled states, focus, or popup anchors. CAT uses it for toolbar groups and active-segment AI/tag actions.
- `ChoiceGroup` presents a single selection as segments or cards using native radios; it owns checked/focus/disabled styles and browser radio navigation. Pages supply options, the selected value, and the business callback. `ToggleButton` remains the control for independent pressed states. Specialized workspace navigation, the editor resize handle, and token rendering stay in their domain components.

Do not add page-local backdrops, menu lifecycle listeners, raw React form controls, or direct primitive-library imports. Extend the shared component's API when a reusable behavior is needed. The [UI boundary check](../apps/desktop/src/renderer/src/components/ui/boundary.test.ts) checks direct controls, internal classes, and page overrides of shared-control appearance, with explicit exceptions for the domain controls above. The [design ownership check](../apps/desktop/src/renderer/src/theme/designBoundary.test.ts) rejects local palette values, arbitrary type sizes, and control-geometry definitions outside their owners. Both checks run in `npm run gate:style`. Adjacent UI tests and [confirmation tests](../apps/desktop/src/renderer/src/services/FeedbackHost.test.tsx) cover focus, nesting, queue decisions and native form behavior. Use the desktop smoke suite to verify the actual Electron focus and editor interactions.

The desktop smoke command runs the [editor suite](../apps/desktop/e2e/editor-engine.smoke.spec.ts) for persistence, selection, and CAT navigation, the [UI controls suite](../apps/desktop/e2e/ui-controls.smoke.spec.ts) for dialogs, menus, tabs, native choice navigation, and resource form/action workflows, and the theme and typography suites linked above. All use isolated temporary user data.

Context below each target uses 10px italic text with a 12px line height and the fixed interface sans-serif stack (Source Sans 3 and Noto Sans SC), independent of body font preferences. Its dedicated `editor-context` palette role uses neutral gray in Sand, warm gray in Classic, and subdued blue-gray in Nord, distinct from each theme's body text while retaining readable contrast. Context is right-aligned on one line; overflow preserves the beginning and truncates the end, and hovering reveals the full text and brightens it for copying.

CAT Western body text uses Source Serif 4 and Source Sans 3 at weight 450 through fixed-weight font-face aliases in the typography owner. It retains the existing weight-only font assets; Chinese fallback, context, interface and workspace typography keep their existing weights. The provider exposes the active typography scope so this default applies consistently in all CAT color themes.

## Editor persistence and events

The active segment exposes one AI button: empty targets translate immediately; existing targets open a refinement popover with an instruction field and an explicit Retranslate action. Escape returns focus to the target editor, while outside dismissal respects the clicked control. Both AI actions await pending segment saves before dispatch. The tag insertion button remains separate. Rows have a shared 64px minimum/estimated height and grow with text and feedback; popovers do not participate in row sizing.

`Editor` composes filters and batch actions with the `useEditor` state controller. `useEditor` composes the segment store, persistence, QA, data loading, and references. Rows edit token-backed local state optimistically; `useSegmentPersistence` coalesces writes per segment and serializes requests for that segment. Different segments may save concurrently.

Confirmation and explicit actions that require saved data must await `flushSegmentUpdate` or `flushAllSegmentUpdates`. A failed save rejects the flush, leaves a visible save error, and retains the latest unsaved target for retry. An older failed request must not replace a newer queued edit. Automatic debounce catches rejection only after recording the failure; an explicit flush must observe it.

`SegmentService` owns the database transaction. The renderer must not independently recalculate repeat propagation or commit Working TM entries. After commit, segment events update the renderer and reference-change events invalidate matching caches.

Remote event coordination belongs in `useEditorDataLoader`:

- Ignore events for other files and stale echoes identified by `clientRequestId`.
- Delay an event while its direct segment or any propagated follower is being edited or has an outstanding local save.
- Apply a batch through the segment store, preserving event order and publishing only the affected segment identities.

The editor's unload/pagehide hooks start a best-effort flush. They are not an awaited application-close protocol; do not use them as proof that pending writes survive immediate process termination.

## Files and background jobs

`ProjectFileModule` owns project file workflows behind `ProjectService`. Renderer file dialogs and hooks collect options and display outcomes; shared parsing and localization behavior stays behind the application adapter. File-level tag policy is persisted with import options and reused throughout the file lifecycle.

Paste imports name the task from the first five filename-safe characters of the first non-empty segment plus the local date (`YYYY-MM-DD`), retaining the CSV extension and adding a numeric suffix on collisions.

The CAT editor toolbar's AI Translate action defaults to the current filtered results when filters are active and offers the entire file as an alternative. Opening the dialog snapshots all matching segment IDs using the latest filter input, including context searches. Display sorting does not change translation order. The Tasks tab translates entire files. Planning, confirmed-row locking, and selected-scope result identity follow the [localization contract](LOCALIZATION.md#mt-request-planning).

Job handlers dispatch long operations through `JobManager` and the corresponding service/worker. The renderer tracks returned job identities and progress; progress notifications do not prove that a write committed. Preserve cooperative cancellation and the workflow's completion/failure outcome when adding UI actions. Reference export, source terminology precheck, and TM/TB sync retain their own [localization contracts](LOCALIZATION.md).

## Changing a desktop boundary

Project/file/segment, TM/TB, AI, job, and dialog handlers narrow incoming arguments before calling a service, lookup worker, job manager, or native dialog. [argumentValidation.ts](../apps/desktop/src/main/ipc/argumentValidation.ts) provides named argument readers and primitive guards. Domain shapes live in [projectPayloadValidation.ts](../apps/desktop/src/main/ipc/projectPayloadValidation.ts) for project/import/segment/token inputs, [referencePayloadValidation.ts](../apps/desktop/src/main/ipc/referencePayloadValidation.ts) for TM/TB inputs, [aiPayloadValidation.ts](../apps/desktop/src/main/ipc/aiPayloadValidation.ts) for AI settings and translation inputs, and [dialogPayloadValidation.ts](../apps/desktop/src/main/ipc/dialogPayloadValidation.ts) for file filters.

Primitive readers validate without coercing, trimming, or copying accepted values. Optional fields distinguish `undefined` from invalid supplied values, and legitimate extension metadata passes through unchanged. AI translation retains its shared [scope parser](../apps/desktop/src/shared/aiTranslationScope.ts), which validates and snapshots selected IDs; empty or sparse selections must fail before job creation. Services retain semantic checks such as resource existence, permissions, distinct sync columns, and mapping review.

Keep shape checks ahead of jobs, notifications, and native dialogs. [handlerArgumentValidation.test.ts](../apps/desktop/src/main/ipc/handlerArgumentValidation.test.ts) exercises malformed arguments, absence of side effects, and accepted payload compatibility. Registration and preload type tests alone do not prove those behaviors. System path handling and clipboard sender checks remain with their owning handlers.

1. Define the typed request/result in `shared/ipc.ts` or its focused shared contract and register the channel in `shared/ipcChannels.ts`.
2. Keep preload forwarding mechanical. Validate untrusted arguments in the owning main-process handler or service before mutation; TypeScript types alone are not runtime validation.
3. Put transactions and jobs in services/modules. Keep pure contracts in `@cat/core` and reusable headless workflows in `@cat/localization`.
4. Update the relevant handler and preload tests together. For UI async changes, test delayed completion, rejection, and newer edits arriving during an older request; use the editor smoke suite for interaction regressions.

Choose the commands from the [validation matrix](DEVELOPMENT.md#validation-strategy). Renderer changes use adjacent component/hook tests and [desktop e2e](DEVELOPMENT.md#desktop-e2e-and-packaging); IPC changes also require desktop typecheck and architecture validation.
